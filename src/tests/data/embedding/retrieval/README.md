# L3 retrieval fixtures — `test_embed_retrieval`

Frozen corpus/query/ranking fixtures for the bge-m3 embedding engine retrieval test (embedding_model_test_plan.md §4.3), generated by the dev-only script `scripts/embedding/gen_retrieval_fixtures.py` (PyTorch fp32 CPU oracle — never the engine). These references are frozen: they are never regenerated to make a test pass (plan §1.1). The sentence-level goldens in the parent directory (`corpus.txt`, `golden_*.bin/json`, `golden_meta.json`, `MANIFEST.json`) are untouched by this generator.

## Layout

* `corpus.jsonl` — 5000 lines, one JSON object per line: `{"id": "p0000".."p4999", "text": "…"}`, UTF-8, LF-terminated. Whitespace runs collapsed to one space, no control characters, so readers can use the raw text verbatim.
* `queries.jsonl` — 200 lines, same shape (`id` runs `q000`..`q199`).
* `golden_dense_scores.fp32.bin` and `golden_sparse_scores.fp32.bin` — raw float32 little-endian, row-major **[200][5000]** = [query][passage], no header, 4,000,000 bytes each. Row *i* is line *i* of `queries.jsonl` (id `q000`, `q001`, …) and column *j* is line *j* of `corpus.jsonl` (id `p0000`, `p0001`, …).
* Line endings are LF, files are UTF-8 without BOM; committed sha256 values are of those exact bytes, so a checkout with `core.autocrlf=true` (CRLF) changes the on-disk hash while the content stays equivalent — read the files as text, not as raw hashes, if your git config converts line endings.
* `qrels.json` — `meta` = this manifest (definitions, dataset revisions, stats, file hashes); `queries` = per query: `dense_top10` / `sparse_top10` (ordered golden rankings), the matching scores, the tie groups (|Δscore| < 1e-05, compared unordered by the test), and `gold_ids` — the *human* relevant passages inherited from the source datasets (advisory: recall/MRR/NDCG baseline inputs).

`corpus_embeddings.fp32.bin` (the engine-built corpus embedding cache of plan §4.3) is deliberately **not** shipped here — the test produces and uses it at review time.

## Reference definitions

* **corpus_line**: {"id":"p0000".."p4999","text":...} UTF-8 LF, whitespace collapsed, no control chars
* **dense**: last_hidden_state CLS row, L2-normalized (fp32); score = dot = cosine
* **gold_ids**: passages the source dataset's human judgments mark relevant for that query (1..5 of them are in the corpus; nfcorpus queries with more judgments keep only their first 5 — see notes)
* **hybrid**: not frozen: derivable as dense + alpha*sparse (bge-m3 default alpha 0.5)
* **matrix**: float32 little-endian, row-major [query][passage], no header; row i is queries.jsonl line i (zero-padded id qNNN) and column j is corpus.jsonl line j (zero-padded id pNNNN)
* **query_line**: {"id":"q000".."q199","text":...}
* **query_src**: provenance tag per query row: nfcorpus / miracl-zh-triples / mmarco-ja-triples / miracl-ko-triples for the 198 eval-set queries, synthetic-gibberish for the q198/q199 negative controls; corpus rows carry the same tags plus miracl-corpus-<lang> (cross-domain filler) and duplicate
* **ranking**: sort by (-score, passage index ascending); groups of top-10 entries within |Δscore| < 1e-5 are reported unordered (plan §4.3)
* **sparse**: lexical weight per token = relu(h @ W_sparse.T + b_sparse), W_sparse/b_sparse from sparse_linear.pt (fp16 values, fp32 math); kept for token ids > 2 (../golden_sparse.json convention), zero weights dropped, max-pooled per token id; score = sum of w_q*w_p over shared token ids, ascending token-id accumulation
* **truncation**: tokenizer truncation at 512 tokens

## How the test consumes this (plan §4.3)

1. Build the corpus library through the engine (`encode_batch` over `corpus.jsonl`) with **truncation at 512 tokens** (`meta.max_seq_len`, the same knob as `../golden_meta.json`); any other truncation changes the reference. Cache the result as `corpus_embeddings.fp32.bin`.
2. Encode the 200 queries, brute-force cosine top-k on the host.
3. Ranking parity: engine ordered top-10 == `dense_top10` for ≥ 99 % of queries, tie groups (`dense_tie_groups`, |Δscore| < 1e-5) compared unordered and reported; then repeat for `sparse_top10` and the dense+sparse hybrid (`dense + α·sparse` with the engine's α) — both score matrices are frozen here, so hybrid rankings are recomputable from them without re-encoding.
4. Metrics: `Recall@10 == 1.0` modulo ties against the golden qrels; report MRR@10 / NDCG@10. `gold_ids` are the *source datasets' human judgments* (advisory baseline — the frozen rankings themselves are model-derived from the golden matrices); the reference MRR@10 / NDCG@10 of this fixture are the values recorded above.
5. Sparse semantics the engine must match: one lexical weight per token id (id > 2, i.e. `<s>`/`<pad>`/`</s>` excluded and `<unk>` kept — the `../golden_sparse.json` convention), relu output, zero weights dropped, max-pooled per token id inside a document, then the dot over shared token ids.
5. Negative controls: gibberish queries (`q198`, `q199`) must stay below the median golden dense score; duplicate pairs must rank adjacent.

## Determinism

Sampling uses a SHA-256 counter PRNG (seed 20261017), all table iterations are sorted or index-addressed, and JSON is written with `sort_keys=True`. Encoding is fp32 CPU torch with `torch.set_num_threads(24)` and a fixed batch order/padding, so a re-run on the same machine and torch build reproduces these sha256 values byte-for-byte (`--verify-only`). On other hardware the last fp32 bits can differ; the committed hashes above stay the frozen reference and ranking parity relies on the tie rule rather than bitwise equality.
